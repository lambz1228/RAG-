# 第二轮开发运行与待评分材料

本目录保存真实本地模型的完整36份输出复核副本，题目12道、每题三组。题集与第一轮相同，参与过开发诊断，因此不是独立测试集。第一轮摘要见[基线摘要](../taskbook-dev-v1/answer-baseline-summary.json)，第二轮见[结构化论断摘要](answer-claims-summary.json)。

第二轮使用 `evidence-v6-structured-claims` 提示与可选JSON Schema输出，由程序校验论断对应的来源编号再渲染引用。基础RAG为9份generated、3份partial；优化候选为7份generated、3份partial、2份provider_fallback。这些是程序状态，不是人工事实分数。两份回退已保留，没有重试替换。

## 如何评分

1. 协调者复制并分发[盲评表.csv](review/盲评表.csv)，不要覆盖原始空白表。真实评分者填写评分、姓名和日期；不要改匿名答卷号、答卷摘要或答案列。
2. 对照原文URL、字符范围和参考要点核对。本文献和参考草稿本身也需要真实人员复核。原文位置基于冻结规范化文本，线上版本变化时重新采集的字符范围可能不同。
3. 协调者保存[运行包](review/评分运行包_协调者保管.json)和[组别映射](review/协调者密钥_勿分发给盲评者.json)，在盲评提交前不要分发。仓库中公开这些文件方便复现；已查看映射的人不应再作为本轮盲评者，可另行开展非盲复核或新盲评。
4. 在网页“检索评估 → 回答质量评价”上传运行包和填写后的CSV。也可运行：

```bash
python scripts/summarize_answer_reviews.py --run research/taskbook-dev-v2/review --reviews 已评分.csv --output output/quality-reviewed-01
```

回退与错误记录可写复核备注，评分字段保持空白，不能当作有效的模型生成答案计入事实成绩；报告会保留它们的数量。本轮最多34份可有效评分：无检索与基础RAG组可在真实评分完整后汇总；含2份回退的优化组会明确显示“含运行失败，无法汇总完整指标”，不能仅靠填写评分消除，也不删去失败记录制造完整成绩。后续修复需另开新版本实验，不覆盖本轮。

当前[评价报告](quality-pending/回答质量评价.md)为0/36，准确性及含无支持断言回答比例均为空。软件不能证明评分者身份、知识水平或评分判断，不代替真实复核。

## 副本边界

[REVIEW_COPY.json](review/REVIEW_COPY.json)记录原运行摘要。复核副本只移除 `citations[].text` 中的长原文，保留其SHA-256及来源定位；模型答案、失败状态和其他信息保留。副本重新绑定答卷摘要，不能混用原机评分表。此处“原文摘要”指SHA-256，不是文献内容概述。完整原库、原始响应和运行数据保留在本机独立目录，未塞进源码仓库。
