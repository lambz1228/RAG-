# 中英文双路查询诊断与回答回归

日期：2026年11月16日。新增功能版本：`dual-query-rrf-v1`，在原双语词项混合检索之上增加问题级英文转换和两路融合。本轮24题已经被观察，所有成绩均为诊断回归，不是新的独立测试成绩。

## 原问题定位

对20道有出处题获取原混合检索前50个候选，逐一核对候选与登记原文区间是否有交集：9题未召回，7题已进前50但未进前5，4题进入前5。排名对象是证据片段，不是仅判断论文标题或来源是否出现。4道指定DOI缺失题单列。

固定术语表难以覆盖新中文表达，因此本轮验证问题级英文转换。没有修改原始题目、参考要点或标准证据，也没有新增逐题路由、指定论文或答案词典。

## 实现

开关为`BIOKB_QUERY_TRANSLATION`，通用默认值为false，本机`.env`已启用。配置示例见`config/deepseek-dual-query.env.example`。关闭该开关即可使用原查询流程，无需重建索引。

1. 对混合检索中的中文问题，保留原问题，先执行原查询。
2. 使用已配置的DeepSeek接口将问题转换为英文检索问题，要求保留否定、比较、数量、物种、条件和标识符，不添加答案。只向转换模型发送原问题，不发送参考答案或标准来源。
3. 原查询、英文查询分别执行既有混合检索，各取最多50个候选，再按RRF融合、按片段去重。检索范围和资料筛选对两路一致。
4. 纯BM25、纯向量、非中文查询继续采用原流程；转换失败或缓存不可用时，显示警告并使用原查询。模型转换可能发生语义偏移，提示约束和格式校验不能保证完全忠实。
5. 本机独立SQLite缓存保存英文表达和原始响应，键包含原问题摘要、提示、模型和接口指纹，最多保留1000条。缓存位于运行数据目录，不在导入模块时创建，不修改正式文献或向量。

模型和转换版本变化时不会复用旧键。失败不写入成功缓存。实验支持只读复制种子缓存，并记录摘要，避免检索诊断与回答回归使用不同的英文表达。当前接口调用显式使用JSON输出、关闭思考模式，最多1024输出词元。

同一冻结库、同一20道有出处题，不重新建立向量。上下文比较均使用混合检索、K=5、相邻证据扩展1层及相同文献数量限制和字符预算。

24条实际英文表达已检查，未发现明显添加答案或改变DOI；这属于助手对转换内容的检查，不是人工或专家审核。实际转换用量为3371输入token、773输出token。后续24题回答回归全部命中这批缓存，没有新增转换调用。该用量不是端到端问答总费用，不包含生成和裁判。

## 回答与自动评价

24题生成完成：18题生成回答、2题部分回答、4题证据不足；接口错误0、摘录回退0，源库未变。由DeepSeek Pro进行相同量表的模型自动评价，24份均成功，保留原始响应。
