# 真实模型与任务书对照实验

## 本地真实模型

本轮使用CPU本地服务，向量为 Qwen3-Embedding-0.6B Q8_0（1024维），生成为 Qwen2.5-1.5B-Instruct Q4_K_M。模型、仓库修订、文件SHA-256和llama.cpp运行时版本见 `research/taskbook-dev-v1/model-provenance.json`。小模型用于完成可复核开发实验，不代表推荐的最终模型或已达到领域准确率目标。

llama.cpp服务启动示例（路径按实际下载位置调整）：

```bash
llama-server -m Qwen3-Embedding-0.6B-Q8_0.gguf --embedding --pooling last --host 127.0.0.1 --port 18081 --ctx-size 2048 --alias biokb-qwen3-embedding-0.6b
llama-server -m qwen2.5-1.5b-instruct-q4_k_m.gguf --host 127.0.0.1 --port 18080 --ctx-size 8192 --alias biokb-qwen2.5-1.5b
```

两个命令在不同终端运行。模型从各自官方Qwen模型仓库取得，不随源码包分发。`config/local-models.env.example`供显式读取；不会自动覆盖现有 `.env`。

## 独立语料与冻结

按登记的PMID重建本轮开发采集库：

```bash
python scripts/collect_taskbook_sources.py --output data/taskbook-collection
python scripts/prepare_taskbook_corpus.py --source data/taskbook-collection/database --output data/taskbook-prepared
```

若官方XML或可获取类型与登记快照不同，重建脚本会保留已取得资料并报告差异，不沿用旧版本标识；允许新来源时需显式使用 `--allow-source-updates`，重新冻结并重新运行。

`prepare_taskbook_corpus.py`复制为新的开发库，保留原库，记录范围排除理由并补入许可明确的样例。它是开发选材，不是专家审定语料。

在独立副本中配置真实Embedding并执行 `python -m biokb --env-file config/local-models.env.example --data-dir <副本> reindex`。可以先用 `create-revision` 把整理库复制为独立语义版本，再在该副本中重建：

```bash
python -m biokb create-revision data/taskbook-prepared data/taskbook-semantic
python -m biokb --env-file config/local-models.env.example --data-dir data/taskbook-semantic reindex
```

确认向量指纹和维度后冻结：

```bash
python scripts/freeze_corpus.py --source data/taskbook-semantic --output data/taskbook-frozen
python scripts/freeze_corpus.py --output data/taskbook-frozen --verify
python scripts/build_taskbook_dataset.py --corpus data/taskbook-frozen --output output/taskbook-dataset.json
```

12道开发题的草稿位于 `research/taskbook-dev-v1/questions.spec.json`。构建器对齐原文位置、区间摘要和冻结库摘要。两道无答案题只验证指定DOI是否在目录中，不代表已覆盖所有真实领域无答案情形。

## 三组对照

```bash
python scripts/run_taskbook_retrieval.py --env-file config/local-models.env.example --corpus data/taskbook-frozen --dataset output/taskbook-dataset.json --output output/retrieval-01
python scripts/run_answer_experiment.py --env-file config/local-models.env.example --database data/taskbook-frozen/knowledge.sqlite3 --dataset output/taskbook-dataset.json --profile taskbook --output output/answers-01
```

`taskbook`包含无检索、基础向量RAG、混合检索加相邻扩展三组。优化组同时改变召回策略和上下文组织，因此只比较整条链路，不把差异单独归因于某一个因素。需要消融时用 `--profile core`（五组）；接通真实重排序后再用 `--profile rerank`（七组）。两类RAG使用相同生成模型、提示词与上下文预算，无检索组使用单独的无证据提示词。

运行拒绝覆盖已有目录，使用冻结库的只读备份。保存完整证据、错误与模型回退；不把回退摘录算作生成成功。

## 真实人工评价

仅向评审者分发 `盲评表.csv`。协调者保存参考要点和 `评分运行包_协调者保管.json`，后者用于汇总与核对，不能在盲评前向评审者透露组名。答卷摘要将评分绑定到具体协议与输出，防止混用不同运行的同名答卷。

评审者依据原文核对事实正确性、完整性和无支持断言。无检索组的引用支持率不适用；它的事实正确性仍可依据同一参考原文评价，不能只因没有引用就把全部答案判错。评分日期和身份由真实人员填写，软件只能核对格式，不能证明其真实性。

填写后在网页“检索评估 → 回答质量评价”上传运行包与CSV，或执行：

```bash
python scripts/summarize_answer_reviews.py --run output/answers-01 --reviews 已评分.csv --output output/quality-01
```

空白评分保留为空值；部分答卷评分不会被放大成总体准确率。无支持断言指标是“含至少一条无支持断言的回答比例”，不是按所有论断条数计算的幻觉率。开发题评分与独立测试成绩必须分开。


## 可选结构化论断

小模型直接生成“正文引用编号”和“引用列表”时可能不一致。`config/local-claims.env.example`启用可选的JSON Schema输出：模型逐条给出论断文本和支持它的来源编号，程序逐条校验编号并渲染为原有回答协议，随后仍执行同一引用校验。未知编号、无来源论断或不一致状态仍失败回退，不凭空补引文。

该方式减少的是展示协议错误；引用编号由程序组织，因此不能把结构通过率当成模型事实能力或幻觉抑制成绩。旧的answer模式仍兼容，默认模板不强制要求供应商支持JSON Schema。模型文件未改变时，也要因为提示、输出模式或约束改变而登记新的实验版本。

仓库中的复核副本可移除长文献正文，只保留答案、来源URL、字符区间和原文摘要。它有独立答卷摘要，不能把原机评分表与副本评分表混用；原始完整证据仍保留在本机冻结库与运行目录。


使用已建语义库启动真实问答工作台：

```bash
python -m biokb --env-file config/local-claims.env.example --data-dir data/taskbook-semantic serve
```

网页使用运行副本；冻结库留作只读实验来源。首次模型启动可能较慢，依机器资源调整线程和生成长度，不能把不同配置混成一次实验。
