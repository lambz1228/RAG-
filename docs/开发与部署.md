# 开发与部署

## 环境与运行

Python 3.10+，声明依赖在 `pyproject.toml`。执行 `pip install -e ".[dev,browser]"` 后，运行 `python app.py` 或 `python -m biokb serve`。Windows 可用 `start.bat`。默认库在 `data/biokb/`，可通过 `--data-dir` 指定独立库。

原始 v26 数据没有随 GitHub 源码上传。本次重构不需要它即可运行；使用在线采集或离线样例建立新库。不要把演示库覆盖到已有科研库。

## 模型配置

将 `.env.example` 复制为 `.env`。Ollama 可将 embedding 与生成后端均设为 `ollama`，填入本机已部署的模型名称和实际向量维度。OpenAI 兼容服务使用 `openai_compatible`，填写服务基址、模型与维度。只有服务确认支持 JSON mode 时才设 `BIOKB_LLM_RESPONSE_FORMAT=json_object`。

密钥可写入本机环境变量，通过 `BIOKB_*_API_KEY_ENV` 引用变量名；不要提交真实 `.env`。重排序使用 `compatible` 后端及服务支持的 `/rerank` 接口，不是所有 OpenAI 兼容提供者都支持该接口。

先运行 `python -m biokb doctor` 核对当前配置与索引。更换 embedding 模型后，先用 `create-revision` 建立独立副本，再在副本中重建索引。默认模板保留 hash / disabled，不会因为有网络就自动调用收费模型。

## 检查与打包

```bash
python -m ruff check src/biokb tests/biokb scripts
python -m ruff format --check src/biokb tests/biokb scripts
python -m pytest -q
python -m playwright install chromium
python scripts/verify_browser.py --output output/check-browser
python scripts/verify_workspace.py --output output/check-workspace
python scripts/verify_research.py --output output/check-research
python scripts/verify_literature.py --output output/check-literature
python scripts/package_source.py --output output/distributions/BioKB-source.zip
python scripts/verify_package.py output/distributions/BioKB-source.zip
```

实验与验收使用新输出目录；源码包不携带 `.env`、正式数据库或运行产物。它包含带许可的示例原文与冻结题库。

## 可选容器

`docker compose -f deploy/compose.yaml up --build` 使用声明的 Dockerfile。对外监听必须设置 `BIOKB_API_TOKEN`；发布服务还需要 TLS 与适当访问控制。当前验收以 Python 源码、wheel 和浏览器为准，未将未实际运行的容器部署称为通过。
