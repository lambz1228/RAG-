# 自动评测方案

当前以自动评测为主。人工或专家评分为可选补充，不作为系统运行、实验执行或毕业设计验收的前置条件。老师任务书要求评价回答准确性与幻觉抑制表现，没有规定必须由专家或人工打分；取消该门槛不等于取消效果评价。

## 已可独立运行的评价

| 内容 | 实现与结果 | 解释范围 |
| --- | --- | --- |
| 检索效果 | `run_taskbook_retrieval.py`、`summarize_semantic_retrieval.py`；Hit@K、Recall@K、MRR等 | 登记来源召回与排序，不是回答准确率 |
| 证据区间覆盖 | `run_answer_experiment.py`；上下文及引用与登记原文区间的覆盖 | 位置覆盖，不证明答案得到语义支持 |
| 生成运行诊断 | 生成、部分回答、证据不足、错误与回退分开统计 | 模型状态不是事实质量分数 |
| 引用和逐字复述检查 | 引用编号契约、完全重复问题时的一次纠错与摘录回退 | 不能发现全部错误、遗漏或改写后的空泛回答 |

以上流程均不要求上传人工评分表。最新真实运行、指标与已知失败见[语义版记录](../research/semantic-dev-v1/README.md)，命令见[运行与验收](真实语义版运行与验收.md)。

## 回答事实质量的自动评价

模型自动裁判尚未接入，也没有这类评分结果。后续应使用与被测模型分开的裁判模型，依据问题、原文及参考要点评价正确性、完整性、引用支持和拒答恰当性。不能仅凭另一个模型同意答案就称为真值。

实施时固定裁判模型、版本、提示和量表，保存原始输出、失败记录、题集与答卷摘要；隐藏被测方案名称，给各组使用相同参考资料与量表。参考要点不发送给被测生成模型。裁判可能误判，结果应明确称为“模型自动评价”，不标为人工或专家确认。

无支持断言可报告为“被裁判模型判定含无支持断言的回答比例”；说明分母、拒答及失败处理，避免与逐条论断幻觉率混用。虚构DOI缺失题只覆盖指定来源缺失，不能代表一般领域无答案能力。新测试题应与参与调试的开发题分开，冻结后不按结果改写。

## 可选人工评分与历史记录

网页“检索评估”中的“人工评分（可选）”默认收起，无评审人员时直接跳过。已有评分导入、答卷绑定和导出继续可用。人工字段由真实人员填写，模型裁判另行记录，不将空白改成零分或已通过。

已有冻结题库、模型运行、空评分表及其摘要不变。历史记录中的0/12、0/36或待人工评价只描述当时的该项状态，不阻塞当前其他评价，也不冒充自动评测已经完成。
