# BioKB 2.0 重构验证记录

> 本文保留 2.0 阶段历史记录。2.1 模型联调见 [2.1 优化验收](2.1优化验收.md)，当前 2.2 科研工作流见[科研证据整改验收](科研证据整改验收.md)；下述默认配置和数量均为 2.0 当时状态。

验证日期：2026-11-04。选题：基于 RAG 技术的生物领域知识库系统研发。

本记录区分工程可运行性、检索基线与真实模型质量。当前系统默认使用 `hash/local-hash-v2` 向量和 `disabled` 生成后端，原文摘录不能称为大模型生成回答。

后续文件清理状态见 [文件清理记录](文件清理记录.md)。下文记录重构验收时的环境和产物；一次性 `.venv-verify` 与旧绘图源码后来移出工作区，历史测试结果及数据没有删除。再次运行安装包验收时先按 [开发说明](开发说明.md) 重建独立环境。

## 环境与验证范围

- Windows、Python 3.12.7；主环境 `.venv` 复用系统包，另用不继承系统包的 `.venv-verify` 安装声明依赖与 wheel。
- 前端为原生 JavaScript 模块；独立无头 Chromium 153.0.8010.12 用于浏览器验收，不操作用户现有浏览器会话。
- 单元和 API 测试使用临时数据库与受控模型替身，浏览器流程也使用独立临时语料。
- 新知识库已有 168 篇文献、460 个分块和 460 个向量。概览截图仅读取正式新库，问答、删除等验收操作在临时库执行。

## 检索基线与编号兼容

语料为当前 168 篇文献，分块长度 800、重叠 120；离线哈希向量 384 维。评估 K=10，最多取 50 个片段，再按文档去重。题目源文件的 `generator_model` 均为 `deepseek-ai/DeepSeek-V3.2`，分别为 60 道基础题、40 道复杂题；它们不是独立专家金标准。

基础题原先使用旧 GraphRAG 清理过的文件名，15 个编号与新库 source_id 不同。根据历史清理规则唯一匹配文件，并逐项验证旧输入等于“标题加完整正文”（规范化后），生成 `basic_source_map.json` 和 `basic_source_map.evidence.json`。题目原文、原编号和源数据均未修改。首次未对齐的 `retrieval_basic.json` 保留为诊断输出，不用于最终比较。

对齐后基础题所需 60 个唯一出处全部可用，复杂题所需 73 个唯一出处全部可用。当前评估器对缺失标准出处直接报错，报告记录映射内容、摘要及原编号。

| 题组 | 检索策略 | Hit@10 | Recall@10 | AllHit@10 | MRR@10 |
|---|---|---:|---:|---:|---:|
| 基础题 60 | BM25 | 0.6500 | 0.6500 | 0.6500 | 0.3000 |

| 基础题 60 | RRF 混合 | 0.5667 | 0.5667 | 0.5667 | 0.2132 |

| 复杂题 40 | RRF 混合 | 0.5250 | 0.3333 | 0.2000 | 0.2203 |

最终报告为 `output/refactor/retrieval_basic_aligned.json` 和 `output/refactor/retrieval_hard_verified.json`，包含逐题排名、数据集摘要、映射摘要、公开配置、索引版本和耗时。本次结果显示，当前离线哈希基线及其融合没有超过 BM25。该结果不能外推为预训练向量模型或 RAG 方法整体无效，也不能与语料、模型、分块不同的历史云模型成绩直接合并。

## 验收期间发现并修复的问题

- CLI 覆盖端口等配置时补充统一值域校验，`--port 0` 明确失败；默认返回数量遵从配置。
- 错误向量索引、异常 Ollama 响应和跨批次维度不一致转为明确业务错误，不留下部分索引。
- 上传任务不再重复返回整篇正文；问答限制证据正文字符数并记录实际用量。
- 请求失败时页面显示原因并恢复按钮；品牌导航、文献最后一页删除后的分页状态已修正。
- PowerShell 中文健康脚本采用 UTF-8 BOM，解决 Windows PowerShell 5 解析失败。
- wheel 安装后的数据根目录改为工作目录，避免落在 Python 安装路径。
- 评估拒绝混合索引版本和缺失标准出处，兼容编号时保留可审计映射。

## 尚未验证的边界

真实 Ollama／云端 embedding 与 LLM 未进行在线联调；受控响应测试不能代替真实模型质量实验。未生成或验收 PyInstaller 可执行文件，也未操作真实桌面浏览器窗口；已测试的是其 Waitress 后端入口。Docker 引擎未运行，因此本轮未构建或启动容器；Nginx 模板和 GitHub Actions 也没有远端执行结果。

当前 SQLite 线性检索及进程内任务队列适用于本项目单机演示规模，未做大规模并发压测。共享令牌没有多用户角色权限。文献移出库后保留归档及历史快照，备份恢复需要同时处理数据库与原始文件。引用编号合法不能证明全文事实受到证据支持。

旧绘图系统的 146 项基线结果独立保留，其中有 6 失败、4 错误、3 跳过；这些历史结果没有被并入当前 81 项通过记录。原始模型实验结果没有改写。

## 复现入口

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check src/biokb tests/biokb
.\.venv\Scripts\python.exe scripts/verify_browser.py
.\.venv\Scripts\python.exe scripts/verify_preservation.py
.\.venv-verify\Scripts\python.exe scripts/verify_runtime.py
```

浏览器脚本需安装 `[browser]` 和 Chromium；数据保护脚本依赖本工作区的重构前哈希清单；运行入口脚本需使用已经安装 wheel 的独立环境。原始实验、语料和本机验证输出不随源码包分发。安装、分发与模型配置见 [部署文档](部署文档.md)，实验复现与编号映射见 [实验设计](实验设计.md)。
