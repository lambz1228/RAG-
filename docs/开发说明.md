# 开发说明

## 环境与安装

Python 3.10 或以上。在项目根目录创建虚拟环境：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

只有在没有 `.env` 时执行最后一步，已有配置应逐项补充。开发环境可以只安装 `requirements.txt`，随后通过 `python scripts/biokb.py` 使用命令行。

主工作环境 `.venv` 使用了 `--system-site-packages`。重构验收曾另建 `.venv-verify` 独立环境验证声明依赖和 wheel，验收完成后该一次性环境已移出工作区，版本记录仍在 `output/refactor/verified-environment.txt`。正式复现按上面的独立虚拟环境步骤安装，既有结果见 [验证记录](验证记录.md)。

## 入口与测试

```powershell
.\.venv\Scripts\python.exe app.py --dev
.\.venv\Scripts\python.exe -m biokb doctor
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check src/biokb tests/biokb
.\.venv\Scripts\python.exe -m ruff format --check src/biokb tests/biokb
```

`pyproject.toml` 将默认测试目录设为 `tests/biokb/`。根目录的旧绘图测试已在清理时归档移出工程，既有基线结果仍保留，不能混入当前知识库主线通过率。主线测试使用临时数据库，模型调用通过受控替身验证契约，不消耗云端模型额度。

独立浏览器验收：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[browser]"
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe scripts/verify_browser.py
.\.venv\Scripts\python.exe scripts/verify_research.py --output output/本轮目录/research_browser
```

脚本创建临时数据库与回环 HTTP 服务，启动独立无头 Chromium，检查上传、检索、问答、导出、历史、评估、移动页面和浏览器异常。结束后关闭它创建的服务与浏览器。`verify_browser.py` 默认报告和截图输出至 `output/refactor/browser/`；新一轮验收应指定 `--output output/本轮目录/browser`，保留旧记录。2.2 新增的 `verify_research.py` 检查论文关联、限定范围、相邻原文与双语页面。`verify_workspace.py` 可选 `--snapshot-data data/biokb` 只对已有知识库概览截图，不向其中导入测试文献。

GitHub Actions 的 `biokb.yml` 面向新主线，旧绘图工作流已随旧测试归档移出工程。工作流文件本地检查不代表已经在 GitHub 执行。

需要再次运行安装包验收时，可重建一次性环境后执行：

```powershell
python -m pip wheel . --no-deps --wheel-dir output\wheel
python -m venv .venv-verify
.\.venv-verify\Scripts\python.exe -m pip install output\wheel\biology_rag_kb-2.2.0-py3-none-any.whl
.\.venv-verify\Scripts\python.exe scripts/verify_runtime.py
```

上述示例使用当前 2.2.0 版本；后续版本需同步修改 wheel 文件名。实际独立环境不要继承系统站点包，并执行 `pip check`。运行验收的数据始终使用临时目录。

源码方式默认从仓库根目录读取 `.env` 和保存相对数据目录。安装 wheel 后，命令行以当前工作目录作为配置根；可用 `BIOKB_DATA_DIR` 指定绝对路径，避免将数据写入 Python 安装目录。

## 扩展方式

- 新增文献格式：在 `ingestion.py` 增加解析分支，返回原文与来源元数据；添加损坏文件与空内容测试。
- 新增向量后端：实现 `embed_batch` 和稳定 `fingerprint`，验证结果顺序、维度和有限数值。
- 新增检索算法：在检索服务中保持证据字段契约，独立记录策略名称，不复用其他策略的结果冒充实现。
- 新增问答能力：保持原文证据、引用校验与明确状态。只有真实合法的模型结果可以标记 `generated`。
- 新增持久字段：采用向后兼容迁移，先备份数据库，在临时副本验证。

## 当前边界

SQLite 中存储向量，进程内执行线性相似度计算，适用于当前数百篇文献的演示规模。分块长度改变只作用于新导入文献；`reindex` 重建向量，不重新切分旧文献。原始文件使用内容哈希归档，文献移出知识库后归档仍保留。

模型地址与密钥只在服务端配置。日志不记录原始模型响应、文献全文或凭据；预期错误使用明确业务异常。模型接口兼容性单元测试不等于已验证所有厂商网关，正式接入后需执行真实模型验收。
