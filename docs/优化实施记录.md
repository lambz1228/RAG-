# 生物领域 RAG 知识库重构实施记录

日期：2026-11-04。当前选题：基于 RAG 技术的生物领域知识库系统研发。

## 重构范围

按照选题将应用主线调整为“文献管理 → 文本处理 → 检索 → 证据问答 → 引用追溯 → 实验评估”。新业务实现于 `src/biokb/`，统一从 Web、CLI 和桌面入口使用应用工厂及同一服务层。

原绘图实现和旧测试在完成重构后归档移出工作区；GraphRAG 工作区、原始数据和既有实验结果仍保留。旧版实施记录原文位于 `docs/archive/illustration/docs/优化实施记录.md`。当前记录没有将旧绘图代码的已知问题描述为已修复。

## 交付内容

1. 后端分层：配置、事务存储、解析分块、模型适配、三种检索、问答、任务队列和评估独立成模块。
2. 前端工作台：概览、文献、检索、问答、历史、评估及配置共七个页面，模块化 JavaScript，桌面与移动布局。
3. 数据迁移：独立新库保存 168 篇文献、460 个分块与向量；原库及 512 个登记数据文件哈希不变。
4. 工程入口：统一 CLI、启动脚本、桌面后端、wheel 包、源码包、Docker 示例、健康检查和主线 CI。
5. 文档体系：根目录介绍与指南、架构、API、开发、部署、实验、迁移及验证记录，旧 Markdown 原文归档。
6. 验证工具：临时库浏览器验收、安装包与启动验收、源码包核验、原数据保护检查及旧出处编号映射。

## 关键实现选择

保留 Flask、SQLite 和原生前端，减少迁移依赖与运行成本；向量使用 SQLite 持久化，当前规模在进程内计算相似度。默认原文和哈希模式可离线演示，真实模型按配置接入。模型失败、证据不足、引用不合法均有可见状态。

文献采用原始字节哈希去重，向量先生成再入库；重建全部成功后原子替换。问答保存证据快照，模型与索引记录指纹。评估使用标准出处，并核验出处覆盖和索引版本，避免将数据对齐错误计入算法成绩。
